# 幽浮2 存档解锁 — Beyond 65535

解除 XCOM 2 存档头上**写死的 65 535 字符上限**，让重度 MOD 环境的存档恢复正常读取。

> **状态：** 已完成逆向定位、补丁实现，并在*天选者之战*中实机验证通过。
> 工具通过字节签名定位补丁点，不绑定于某一个游戏版本。

## 问题

MOD 装得足够多以后，XCOM 2 会开始把你的存档标记为**损坏**（读取列表中显示红色、弹出
*"SAVE OUT OF DATE"*，点 *LOAD ANYWAY* 后则是 *"load failed"*）。**存档本身是完好的，
只是游戏拒绝读取它。**

社区流传的解释是「所有 MOD 名称的总长度超过了 65 535」。**这个解释是错的。**
对十余个真实存档做过实测，没有任何一个「名称总长」的统计量能预测哪些存档会坏。
真正能预测的只有一项：

| 存档文件 | 头部长度字段（`a4`） | 能否读取 |
|---|---:|---|
| `save_传承行动 1：任务6，回合1` | 601 | 可以 |
| `save_榴莲_3` | 16 847 | 可以 |
| `save_sora` | 49 663 | 可以 |
| — | **65 535（上限）** | — |
| `save_快速保存：战役97，任务16，回合1` | 66 913 | **不可以** |
| `save_保存 12` | 72 822 | **不可以** |
| `save_RAN` | 72 822 | **不可以** |

存档**文件偏移 0x04** 处的 dword 是存档头的长度。它恰好会随 MOD 列表增长，
这正是那个误解得以流传的原因。真正的规则只有一句：

> **`a4 > 65535` ⟺ 存档无法读取。**

## 原因

存档格式内部的**所有**长度字段都是 32 位的——整个格式里没有任何一个 16 位字段。
限制位于游戏可执行文件里，是读取存档头的函数中一处写死的比较：

```asm
81 7d 38 00 00 01 00   cmp  dword ptr [rbp+0x38], 0x10000   ; a4 与 65536 比较
0f 87 c7 00 00 00      ja   <failure>                        ; 超限 -> 直接失败
```

这是**整个可执行文件中唯一一处把存档头字段与 65 535 做比较**的地方。
写入端没有任何检查——这也解释了为什么打过补丁的安装可以顺利*保存*出 72 968 字节的头部：
**瓶颈从来只在读取路径上。**

完整的反汇编、函数边界、哈希校验与证据链见
[`docs/TECHNICAL.md`](docs/TECHNICAL.md)。

## 修复方式

改动立即数中的**一个字节**：

```
修改前:  81 7d 38 00 00 01 00     cmp ..., 0x00010000   (64 KiB)
修改后:  81 7d 38 00 00 40 00     cmp ..., 0x00400000   (4 MiB)
                    ^^
                 仅此一字节（01 -> 40）
```

指令编码结构未受破坏，可执行文件依然结构有效。把打过补丁的可执行文件与原版备份
做逐字节比对，差异**恰好只有一个字节**。

## 使用方法

同一个补丁有两套实现，都是按字节签名定位、都在写入前自动备份、都经过同等验证。

**PowerShell 版**——不需要 Python，任何现行 Windows 都能跑：

```console
powershell -ExecutionPolicy Bypass -File tools\SaveFix.ps1 Status
powershell -ExecutionPolicy Bypass -File tools\SaveFix.ps1 Apply
```

**Python 3.8+ 版**——**仅用标准库**，无需 `pip install`：

```console
# 获取仓库
git clone https://github.com/A16Nights/xcom2-savefix.git
cd xcom2-savefix

# 1. 查看工具找到了什么，以及你的游戏是否已经打过补丁
python tools/xcom2_savefix.py status

# 2. 打补丁（默认 4 MiB）。请先关闭游戏——它会锁定可执行文件。
python tools/xcom2_savefix.py apply

# 3. 检查你的存档
python tools/xcom2_savefix.py saves
```

修改任何内容之前，会在可执行文件旁写入备份 `XCom2.exe.65535bak`。

```console
# 换一个上限（1 到 4096 MiB 之间的任意值）
python tools/xcom2_savefix.py apply 16

# 完全还原
python tools/xcom2_savefix.py restore

# 只预览将要做什么，不写入
python tools/xcom2_savefix.py apply 8 --dry-run
```

工具会通过 Steam 注册表和 `libraryfolders.vdf` 自动探测游戏位置，
同时支持原版与*天选者之战*。如果猜错了，用 `--exe PATH` 显式指定。

### 支持的可执行文件

| 版本 | 限制点位置 | 全新安装中的状态 |
|---|---|---|
| 天选者之战 | RVA `0xa57d6c`，文件偏移 `0xa5736c` | `cmp ..., 0x10000` |
| 原版 | RVA `0xa0617c`，文件偏移 `0xa0557c` | `cmp ..., 0x10000` |

地址仅供参考——工具通过签名定位（`81 7d 38 ?? ?? ?? ?? 0f 87 ?? ?? ?? ?? 83 7b 4c 00 74 29`），
该签名在两个可执行文件里都**恰好只命中一处**。若命中零处或多处，工具会拒绝操作，而不是猜测。

## 使用前你应该知道

* **打补丁前请关闭游戏。** Steam 会锁定可执行文件。
* **Steam 的「验证游戏文件完整性」以及游戏更新会还原原版可执行文件。** 之后重新运行 `apply` 即可。
* **存档不向前兼容。** 在提高上限的安装上写出的存档，无法在未打补丁的安装上读取。
  `restore` 可以让你回到原版行为。
* **多人对战 / 挑战模式排行榜。** 本补丁面向**单人游戏**。请勿用于排位或共享存档模式——
  修改过的可执行文件不是对手同意过的。
* **这是不受支持的修改。** 与 Firaxis Games、2K、Take-Two 均无关联，未获其认可或支持。
  详见 [`DISCLAIMER.md`](DISCLAIMER.md)。

## 验证方式

* **静态验证。** 该限制点是整个 `.text` 段中**唯一**以内存为操作数的 `cmp ..., 0x10000`；
  其所属函数通过 PE 异常目录（`.pdata`）确认；该签名在原版与天选者之战两个版本中均唯一命中。
* **运行时验证。** 在限制点被挂钩的情况下，**52/52** 次存档头读取全部返回成功，
  **52/52** 次头部哈希校验全部匹配，其中 **24** 次按原规则会被拒绝。
  所有超限头部（`66913`、`72690`、`72822`、`72834`、`72838`、`72870`、`72880`、`72902`）
  均被放行。
* **文件级验证。** 在**没有任何进程注入**在运行的情况下于磁盘打补丁，
  再把已映射的可执行文件读回来，看到的仍是打过补丁的立即数——
  证明该改动来自文件本身，而非某个正在运行的调试器。
* **游戏内验证。** 原先无法读取的存档（列表中显示红色）现已正常载入。

## 仓库结构

```
tools/xcom2_savefix.py    补丁工具，Python 版（status / apply / restore / saves）
tools/pe_util.py          零依赖的 PE 读取器与字节模式扫描器
tools/SaveFix.ps1         同一个补丁工具的 PowerShell 版，不需要 Python
workshop/                 创意工坊条目：清单、说明、启动器、预览图
docs/TECHNICAL.md         限制点是如何定位的：反汇编与证据
docs/SAVE_FORMAT.md       存档文件头部布局
README.zh-CN.md           本文件
DISCLAIMER.md             法律声明
```

`workshop/` 存放发布到 Steam 创意工坊的条目文件（**[WOTC] Savefix — Beyond 65535**）。
工坊条目内附的是 PowerShell 版工具，订阅者拿它去改自己机器上的可执行文件，
因此条目本身**不含任何游戏文件**。

## 相关工作

Steam 创意工坊 MOD **[WOTC] Too Many Mods** 走的是另一条路：它把写入存档的 MOD 列表
截短，让头部保持在限制以内。那是**绕过**问题，并且可能静默丢掉重要的 MOD。
本项目则是**移除限制**。
